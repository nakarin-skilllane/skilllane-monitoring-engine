วัตถุประสงค์

หน้าของ error group เดียว (ORA-12899) สำหรับคน on call และ tech lead: อ่านจากบนลงล่างแล้วได้คำตอบตามลำดับ เกิดอะไร → กรณีนี้ต้องแก้อะไร → แก้ที่ไหนในโค้ด → error จริงและ stack → เกิดเมื่อไหร่ เกี่ยวกับ deploy ไหม → route/version ไหน → ใครโดน แล้วคัดลอกทั้งหมดให้ AI ได้ในปุ่มเดียว (requirement 4 และ 5) · group 2 ซึ่งเป็น error ใหม่หลัง deploy มีหน้าของตัวเองที่ error-detail-null-read.html

ข้อมูลมาจาก

  • ทั้งหน้า: GET /api/errors/:fingerprint?env=prod&from=now-24h
  • หัวหน้า + KPI: group.hint, errorCode, errorType, category, level, service/role, count, users, firstSeen (ทั้งข้อมูลที่เก็บไว้), firstSeenVersion, isNew, lastSeen, fingerprint
  • เกิดอะไรขึ้น: group.hintDetail · กรณีนี้: group.fix (ของครั้งล่าสุด)
  • แก้ที่ไหน: group.routes[0], usecases[0], originFunction, originFile, target, failedStep
  • Error จริง: errorType + errorCode + sampleMessage; stack จาก recent[0].error.stack (frame ที่ไม่ขึ้นต้นด้วย node_modules หรือ node: = โค้ดแอป)
  • กราฟ: series[{t,count}] step 15 นาที UI รวม 4 ช่องเป็น 1 ชั่วโมงนับจาก from (ช่องเริ่มที่ :20) ตัวเลข 24 ช่องเท่ากับแท่งของ group นี้ในหน้า Error ทุกช่อง · เส้น deploy: /api/meta deploys · คอลัมน์ Version: versions ของ /api/errors/:fingerprint (SPEC §12 C)
  • Route และ usecase: routes[{route,count}], usecases[{usecase,count}] · ท้าย panel: /api/overview routes[]
  • ครั้งล่าสุด: recent (LogRow 20 แถว): timestamp, userId, userRoles, organizationId, version, traceId; http.status และ durationMs ต้องให้ API join จากบรรทัด http.request ของ trace เดียวกัน (ข้อเสนอ DESIGN.md §9)
  • Markdown ให้ AI: สร้างฝั่ง UI จาก group + stack ของ recent[0] ด้วย template เดียวกับทุกหน้า ไม่ใส่ userId / organizationId / role
  • ตัวเลขรายชั่วโมงเป็นตัวอย่างที่รวมได้ 214 และแบ่งเป็น 71 / 143 ตาม version; trace id อื่นนอกจาก 4bf92f35…, fingerprint และเลขบรรทัดใน stack เป็นค่าสมมติ

การโต้ตอบ

  • คัดลอกให้ AI (หัวหน้าและในกล่อง Markdown) คัดลอกข้อความในกล่องทุกตัวอักษร ปุ่มเปลี่ยนเป็น "คัดลอกแล้ว" 1.6 วินาที
  • เปิด trace ตัวอย่าง → trace-detail.html (group.sampleTraceId) · ดู log ทั้งหมด → logs.html?q=ORA-12899&route=POST /question-bank/import&level=error จนกว่า /api/logs จะรับ fingerprint
  • ปุ่มคัดลอกเล็กข้าง fingerprint, function, ไฟล์ และ trace id
  • "ดู span นี้ใน trace ตัวอย่าง" เปิด trace-detail โดยเลือก span ที่ error ไว้
  • กราฟ: ชี้หรือแตะแท่งเพื่อดู tooltip (ช่วงเวลา, ครั้ง, version) · "ดูเป็นตาราง" มีทุกค่า เป็นทางเลือกสำหรับคีย์บอร์ด · จอแคบเลื่อนไปช่วงล่าสุดก่อน
  • Stack: เห็นเฉพาะ frame ของแอปก่อน stack เต็มอยู่ใน details ที่ปิดไว้ ปุ่มคัดลอกได้ stack เต็มพร้อมขึ้นบรรทัด
  • ตาราง ครั้งล่าสุด: user id → Log กรองตาม user · trace id → trace-detail (ใน mockup ทุกลิงก์เปิด trace 4bf92f35…)
  • เปลี่ยนช่วงเวลา: จำนวนครั้ง กราฟ และตารางเปลี่ยนตาม แต่ "ครั้งแรก" ยังคิดจากข้อมูลทั้งหมดที่เก็บไว้
