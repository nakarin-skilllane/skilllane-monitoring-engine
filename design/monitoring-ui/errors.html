วัตถุประสงค์

  • ตอบ developer on call และ tech lead หลัง deploy: error อะไรเกิดบ่อย ใครโดน ต้องแก้ที่ function และไฟล์ไหน และ group ไหนเพิ่งเกิดหลัง 31.4.0
  • ทุกแถวใช้กติกา readable error: หัวข้อ = error_hint + error_code, ต้องแก้อะไร = error_fix ของครั้งล่าสุด (ไม่มีใช้ error_hint_detail) แสดง 2 บรรทัดเต็ม ๆ, ที่ไหน = source · file · route หรือ job · target, หมวดเป็นภาษาคน, service/role ทุกแถว
  • ERR อยู่บน WRN เสมอ (เรียงภายในกลุ่ม) และแถว WRN (4xx) เบากว่า: ตัวหนังสือ ink-2 น้ำหนัก 500 แท่งสีจางกว่า เพื่อให้ 2,771 ครั้งของ 404 ไม่กลบ ERR 214 ครั้ง · group 3 เป็น ERR พร้อมบรรทัดย่อย "38 retry · 3 ล้มเหลวจริง" แบบเดียวกันทุกหน้า

  • KPI: ERR 302 ครั้ง = ผลรวม count ของ group ระดับ error (group 3 นับเฉพาะ 3 ครั้งที่ล้มเหลวจริง) · ชั่วโมงล่าสุด 116 ครั้ง = 47 + 65 + 3 + 1 ซึ่งหน้า Log เห็นเป็น 228 บรรทัด ERR เพราะทุก request ที่ตอบ 5xx (112) มีบรรทัด http.request อีกบรรทัดที่ไม่นับเป็น group · WRN 3,464 · group ใหม่ = isNew (firstSeenVersion = 31.4.0)

  • ค่ารายชั่วโมงเป็นตัวอย่างแต่ผลรวมตรง BRIEF และชั่วโมงล่าสุดตรงกับ route ในหน้า Overview (47 = 11.4 % × 412, 65 ≈ 1.9 % × 3,480, 277 = 3.1 % × 8,940, 65 ≈ 1.1 % × 6,120; group 7, 8 เป็น 0 เพราะ route ของมันไม่มี 5xx ในชั่วโมงนี้) · ค่าที่ BRIEF ไม่ให้และใส่เป็นตัวอย่าง (fix ของ group 3, 4, 7, 8; users ของ group 3, 6, 7, 8; ครั้งแรก/ล่าสุดของ group 3–8) หน้าอื่นใช้ค่าเดียวกัน

  • หัวข้อ group: group 1 → error-detail.html, group 2 → error-detail-null-read.html (mockup มีหน้า detail สองหน้า; ของจริงเป็น /errors/:fingerprint) · group อื่นเป็น anchor #g3–#g8 ของแถวในหน้านี้ ซึ่งหน้าอื่นลิงก์มาและแถวจะถูกไฮไลต์
