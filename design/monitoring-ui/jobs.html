วัตถุประสงค์

On-call ดูว่างานเบื้องหลังของแอป (BullMQ, Kafka, RabbitMQ, cron) ทำครบไหม อะไรล้มเหลวจริง อะไรแค่ retry แล้วผ่าน และระบบที่เรียกใช้ล่มช่วงไหน นานเท่าไร สถานะนั้นมาจากบรรทัด log ไหน หน้านี้ทำให้เห็นข้อ 1 (service/role ของทุกกลุ่ม), ข้อ 5 (error อ่านง่าย บอกที่แก้) และข้อ 4 (คัดลอกให้ AI ใน drawer)

ข้อมูลมาจาก

  • Callout และ KPI: ผลรวมของ GET /api/jobs?env=prod&from=now-24h → stats[] (failed, retried = retry + redelivered, started) และ GET /api/dependencies → dependencies[].state (ณ to, ย้อนดู 7 วัน)
  • ตาราง queue: stats[] (JobStat: service, role = หัวกลุ่ม, module, queue, type, started, finished, retried, failed, p95Ms, lastRunAt, lastFailedAt); ล้มเหลวล่าสุด = แถวใหม่สุดของ recentFailures[] ต่อ queue + type
  • เหตุการณ์และบรรทัดที่ขยาย: consumerEvents ของ /api/jobs (consumer.rebalancing, consumer.joined, job.redelivered)
  • รายการ report:generate: recentFailures[] (LogRow) ที่ job.queue = report: job.id, job.attempt / maxAttempts, job.final, error.hint, durationMs, traceId; กล่องบนสุดคือ ErrorGroup จาก /api/errors (jobQueue, jobType, fix ของครั้งล่าสุด)
  • Drawer: LogRow แถวนั้นทั้งแถว; Markdown สำหรับ AI ประกอบฝั่ง client ด้วย template เดียวกับทุกหน้า (DESIGN.md §6b)
  • ตาราง dependency: dependencies[] (service, role, type, name, host, port, state, since, lastEventAt, lastOutageMs, affects, attempts = บรรทัดที่ล้มเหลวในช่วงนี้); แถบ 24 ชั่วโมง กราฟขยาย และบรรทัดที่ขยาย: events[] (dependency.down / still_down / up และ http.outbound_failed)
  • ค่าที่ dataset ไม่ได้ให้เป็นตัวอย่างที่ไม่ขัดกับ dataset: เวลาที่ล้มเหลว, job id, trace id ยกเว้น e7c3d2a1…21b6, สาเหตุของ export และ cron, path ไฟล์, เวลา redeliver, retry ของ redis (still_down 6, up 9 ตรงกับหน้า Log); p95 ของ lms.sync และ cron ไม่มีใน dataset จึงแสดง – · ในชั่วโมงล่าสุดมี attempt ที่ล้มเหลว 5 ครั้ง (#88391 × 3, #88412 × 2) จาก 240 = 2.1 % ตรงกับแถว worker ในภาพรวม

การโต้ตอบ

  • ปุ่ม BullMQ / Kafka / RabbitMQ / cron กรองตาราง queue (ซ่อนกลุ่มอื่น) ของจริงควรเก็บใน URL ?source=
  • ลูกศรหน้าแถวขยายบรรทัด log ที่อยู่เบื้องหลังตัวเลขนั้น; redis cache เปิดไว้เป็นตัวอย่าง
  • กดเลข job (#88412) เปิด drawer (modal, mockup มีแถวเดียว; ?drawer=job เปิดตอนโหลด); trace id เปิด trace-detail.html และมีปุ่มคัดลอก
  • แถบผลลัพธ์ ขีดบนแถบ 24 ชั่วโมง และกราฟขยายมี tooltip ทั้งเมาส์และ Tab; ตัวเลขเดียวกันอยู่ในตารางเสมอ
  • Callout พาไปที่ section ในหน้านี้; ลิงก์ Log เปิด logs.html พร้อมตัวกรอง event · ชื่อ error group เปิดแถวของมันใน errors.html
  • จอแคบกว่า 600 px: แถว queue และแถวที่ล้มเหลวเรียงเป็นหลายบรรทัด ตัวเลขมีป้ายกำกับ ไม่ต้องเลื่อนข้าง

คำถามที่ยังเปิดอยู่

  • library ไม่ log cron expression: "ทุก 15 นาที" ต้องเพิ่ม field หรือเดาจากระยะห่างของรอบ (lastRunAt บอกได้แค่รอบล่าสุด)
  • ThaID 401 มาจาก http.outbound_failed (อยู่ใน events แล้ว): ควรมี state degraded ใน Dependency ไหม (ตอนนี้มีแค่ down | up)
  • p95 คิดจาก job.finished อย่างเดียว หรือรวม attempt ที่ล้มเหลว (~10 s)
  • Hint ใน library จริงเขียน "Google rate limit hit" และ "Redis "cache" unreachable" แต่ BRIEF ใช้ "Google API rate limited" และ "Redis "cache" refused connection" ใช้ชุดไหน
