ใส่อะไร ไม่ใส่อะไร

ใส่

  • error ของ trace ตาม template เดียวกับทุกหน้า (DESIGN.md §6b)
  • span ที่พังพร้อม peer และ statement ที่ใส่ค่าเป็น :1, :2
  • ต้นไม้ span 13 ตัวและ log 4 บรรทัดของ trace
  • trace id ให้ AI อ้างอิงกลับได้

ไม่ใส่

  • user_id, organization_id และ role ของ user
  • ค่าของ parameter ใน SQL, request body, ชื่อไฟล์ที่อัปโหลด
  • IP, user agent, header
หมายเหตุการออกแบบ

วัตถุประสงค์

Dev ที่ถือ trace id หนึ่งตัว (จาก header request-id, จากหน้า Error หรือ Log) ต้องเห็นในหน้าเดียวว่า request นี้ผ่าน service ไหน เวลาหมดไปที่ขั้นไหน พังที่ span ไหน และต้องแก้อะไร ตอบข้อกำหนดข้อ 3 (per-request tracing) ข้อ 5 (error ที่บอกว่าแก้ตรงไหน) และข้อ 4 (คัดลอกให้ AI)

ข้อมูลมาจาก

  • ทั้งหน้าเรียกครั้งเดียว: GET /api/traces/4bf92f35… → { traceId, start, durationMs, services, spans, logs }
  • หัวหน้า: route และ status จาก span ที่ไม่มี parentSpanId (http.method/route/status), เวลา start, service จาก services; user และโรงเรียนจาก logs[].userId / organizationId เพราะ SpanRow ไม่มี user
  • KPI: durationMs, spans.length, error = span ที่มี exception, เวลาใน school-etl-api = durationMs ของ span SERVER ของ service นั้น; p95 ของ route มาจาก /api/overview routes[].p95Ms (เรียกเพิ่ม)
  • Callout: span ที่ statusCode = ERROR และมี exception + log ระดับ error ใน logs[] (error.hint, error.fix, failedStep, error.originFunction); 214 ครั้ง · 37 users มาจาก /api/errors/:fingerprint โดยใช้ logs[].fingerprint ของบรรทัด error
  • Waterfall: จุดเริ่ม = startTime − start, ความยาว = durationMs, ย่อหน้า = parentSpanId, สี = service, ป้าย = kind, ลูกศร = peer; หมุด log จาก logs[].timestamp, level และ spanId (หมุดซ้ำบนแถวของ span เจ้าของ)
  • Span ที่เลือก: SpanRow ทั้งแถว (kind, service, role, startTime, durationMs, statusCode, statusMessage, db, peer, exception, attributes, events); Resource มาจากคอลัมน์ resource ของ ClickHouse
  • Log: logs[] เรียงตาม timestamp แสดงตามกติกา readable error (หัวข้อ = hint → title ของ event → message, ข้อความเล็กหน้าหัวข้อ = eventCode หรือ logger); ป้าย version จาก LogRow.version / SpanRow.version; สรุปสำหรับ AI ประกอบฝั่ง client จาก response เดียวกัน (ไม่ใส่ user)

การโต้ตอบ

  • Motion: แถบ span โตจากซ้ายไปขวาตามลำดับเวลาเริ่ม (หน่วงตาม --s, รวมไม่เกิน 700 ms) ให้เห็นลำดับการเรียก · span ที่ error มีวงแดงกระเพื่อมหนึ่งครั้ง · หมุด log โผล่ตามเวลาของมัน
  • คลิกหรือกด Enter ที่ span ไหนก็ได้ → แถวมีแถบ accent และ panel "Span ที่เลือก" เปลี่ยนตาม (ของจริงเก็บใน URL ?span=<spanId>; เปิดหน้ามาเลือก span ที่ error ตัวแรกให้)
  • หมุด log: hover หรือ focus แสดงเวลา level และข้อความ; คลิกแล้วเลื่อนไปที่บรรทัด log นั้น
  • ลิงก์ "Parent", "span #…" และ "failed step" เลือก span นั้น; ปุ่ม "ดู span" ใน callout ก็เช่นกัน
  • คัดลอก trace id, span id, ลิงก์หน้า และ "คัดลอกให้ AI" (Markdown ในกล่อง "สรุปสำหรับ AI")
  • "ดู log ของ trace นี้" และ "เปิดใน Log" → logs.html?traceId=…; ชื่อ error และ "เปิด error" → error-detail.html; user → Log กรองตาม user
  • จอแคบกว่า 720 px: แต่ละ span เป็นสองบรรทัด (ชื่อ + เวลา / แท่งเต็มความกว้าง) แกนเวลาเดียวกันทุกแถว ไม่ต้องเลื่อนข้าง; "ดูเป็นตาราง" ให้ค่าครบทุก span

คำถามที่ยังเปิดอยู่

  • errorCount: span #1 ก็มี status ERROR เพราะตอบ 500 หน้านี้นับ "error 1" = span ที่มี exception (#11) ตาม dataset engine จะนับแบบนี้ไหม
  • SpanRow มี version, host แล้ว แต่ยังไม่มี resource และ user: หน้านี้เอา user จาก logs[] และ Resource จากคอลัมน์ ClickHouse ควรให้ API ส่ง resource มาใน SpanRow ไหม
  • exception ของ span เป็น error ของ driver (Error ORA-12899) ส่วน log เป็น QueryFailedError ของ TypeORM แสดงทั้งสองแบบนี้เข้าใจง่ายพอไหม
  • trace ที่มีหลายร้อย span ต้องพับ/ขยาย subtree และค้นหา span (ยังไม่ได้ออกแบบ) · span ที่เลือกเก็บใน URL ?span=<spanId> และเปิดหน้ามาเลือก span ที่ error ตัวแรก ตกลงไหม
  • span id ทั้งหมด, peer ของ Oracle และ db.statement ของ span อื่นนอกจาก #11 เป็นค่าตัวอย่าง dataset ไม่ได้ระบุ
