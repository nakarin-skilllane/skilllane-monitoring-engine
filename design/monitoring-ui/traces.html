วัตถุประสงค์

หา request หรือ job ที่ช้าหรือ error ในช่วงเวลาที่เลือก แล้วเปิด waterfall ของ trace นั้น (requirement 3: trace ราย request) กราฟบอกว่าเกิดตอนไหนและกระจุกที่ความยาวเท่าไร ตารางบอกว่า trace ไหน ของ service/role อะไร ผ่านกี่ service

Entry span คืออะไร

  • span แรกของ service หนึ่งใน trace: ไม่มี parent หรือ parent มาจากอีก process (is_entry = 1 ใน skilllane_monitoring.spans) เช่น HTTP SERVER span, BullMQ/RabbitMQ/Kafka CONSUMER span, cron
  • หน้านี้แสดง 1 แถวต่อ trace คือ entry span ที่ไม่มี parent เลย (root) entry span ของ service ปลายทาง เช่น POST /etl/parse-excel ของ school-etl-api ใน Trace A ไม่ขึ้นเป็นแถวแยก แต่ไปอยู่ในคอลัมน์ "ผ่าน service"
  • job ที่เริ่ม trace ใหม่ (link กลับไปที่ producer) จึงเป็นแถวของตัวเอง เช่น Trace C (attempt 2/3 ของ #88412)

ข้อมูลมาจาก

  • กราฟและตาราง: GET /api/traces ด้วย env=prod, from=now-1h, service, role, kind, route (METHOD /path หรือ job type), status, minMs, limit=100 ใช้ rows[] ชุดเดียวกัน (x = timestamp, y = durationMs, สี = isError / ช้า, รูปร่าง = kind)
  • ตัวอย่าง 100 จุดจาก 1 ชั่วโมงต้องใช้ param ที่เสนอเพิ่ม sample=errors,slow,spread (error ก่อน แล้วช้าสุด แล้ว N ต่อนาที) และ total ใน response; หัวคอลัมน์ "เวลาที่ใช้" ใช้ sort=durationMs (รายการรวมใน DESIGN.md §9) · ถ้าไม่มี limit แถวล่าสุดที่ ~1,900 request/นาที ครอบคลุมแค่ไม่กี่วินาที
  • Span, Error, ผ่าน service: spanCount, errorCount, services[] (จาก skilllane_monitoring.trace_index) · สถานะ: status = HTTP status (0 สำหรับ job), statusCode, isError
  • job id และ attempt ในแถว job (#88412 ล้มเหลว 2/3): เสนอเพิ่ม rows[].job: {queue, type, id, attempt, maxAttempts} | null จาก attribute ของ entry span; ถ้าไม่เพิ่ม แถวจะแสดงแค่ job type และ id ย้ายไปอยู่ในแถวที่ขยาย (โหลดจาก /api/traces/:id logs[])
  • ตัวเลือก service/role: GET /api/meta; ตัวเลือก route และ job: overview.routes[] (kind + route)
  • แถบ Redis down: GET /api/dependencies (events dependency.down/up)
  • แถวที่ขยาย (error ตามกติกา readable error): โหลดเมื่อกดจาก GET /api/traces/:traceId → logs[] ที่มี error · ช่อง trace id: เปิด /api/traces/:traceId ตรง ๆ (trace-detail.html)
  • จุดใน 1 ชั่วโมงเป็นตัวอย่างที่วาดให้สมจริงรอบ p95 ของแต่ละ route ใน BRIEF โดยไม่ขัดกับ dataset: 5xx มีเฉพาะ GET /classes/:id/report และ POST /question-bank/import, trace ช้าสุดของ /classes/:id/students คือ Trace B, ECONNREFUSED ช่วง Redis down เป็น span error ใน request ที่ยังตอบ 200, job #88391 ล้มเหลวครบ 3/3 13:58 และ #88412 ตาม BRIEF

การโต้ตอบ

  • ตัวกรองทุกตัวเปลี่ยนทั้งกราฟและตารางพร้อมกัน และอยู่ใน URL; "ล้างตัวกรอง" ใช้ได้เมื่อมีตัวกรอง
  • ชี้หรือ focus จุดบนกราฟเพื่อดูเวลา, route/job, status, service; จุด error และจุดช้า focus ด้วย Tab ได้; คลิกจุดเปิด trace · จอแคบกราฟเลื่อนไปช่วงล่าสุดก่อน (A, B, C อยู่ในจอ)
  • คลิกแถวหรือชื่อ route เปิด trace-detail.html (ม็อกอัปมีหน้า detail ของ Trace A เท่านั้น); ปุ่มลูกศรของแถว error ขยายดู error, ต้องแก้อะไร และ "คัดลอกให้ AI"; ชื่อ error เปิดหน้า error group ของมัน
  • หัวคอลัมน์ "เวลาที่ใช้" เรียงช้าสุดก่อนได้ (ในม็อกอัปยังไม่ทำงาน); ปุ่มคัดลอกข้าง trace id
  • จอแคบกว่า 600 px: แต่ละแถวเป็น 4 บรรทัด (เวลา · สถานะ · เวลาที่ใช้ / route หรือ job / service / span · error · trace id)
  • แกนตั้งแบบ log (5 ms ถึง 20 s) เพื่อให้ GET /me 14 ms และ job 10 s อ่านได้ในกราฟเดียว แถบในตารางเป็นเส้นตรงเทียบแถวที่นานที่สุด

คำถามที่ยังเปิดอยู่

  • /api/traces ยังไม่มี param traceId: ช่อง trace id ค้นด้วยต้น id (prefix) ได้ไหม หรือเปิดได้เฉพาะ id เต็ม 32 ตัว
  • เกณฑ์ "ช้า" ของ request ใช้ 2 s คงที่ หรือเทียบ p95 ของ route; job ใช้ p95 ของ queue จาก JobStat.p95Ms แทนดีไหม (ตอนนี้ job ไม่ถูกทำสีช้า)
  • 4xx (เช่น 404, 400) นับเป็น ok ตาม span status ของ OpenTelemetry ถูกต้องไหม หรือควรมีตัวเลือกสถานะ 4xx · request ที่ตอบ 200 แต่มี span error (ECONNREFUSED ของ cache) นับเป็น error ตาม errorCount > 0 แบบนี้ไหม
  • กรอง service = school-etl-api ควรหา trace ที่ service นั้นอยู่ปลายทางด้วยไหม (ตอนนี้ดูเฉพาะ root entry span)
  • route ของ video-transcoder-api (GET /videos/:id/status, POST /videos/:id/transcode) เป็นชื่อสมมติเพราะ BRIEF ไม่ได้ระบุ
  • ใส่การลากเลือกช่วงบนกราฟ (brush) เพื่อกรองเวลาและความยาวพร้อมกันใน phase ถัดไปหรือไม่
